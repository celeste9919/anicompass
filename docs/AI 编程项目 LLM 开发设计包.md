# 《AI 编程项目 LLM 开发设计包》

## 1. 项目定位

AniCompass 是一款跨平台桌面日本/亚洲动漫推荐与观看清单管理工具。AI 负责理解用户偏好和生成推荐理由，动漫目录服务负责核验作品身份和基础资料，本地数据库负责清单、历史和设置。全球动画覆盖作为后续扩展，不阻塞首版。

## 2. 需求理解与合理假设

### 用户明确确认

1. Windows `.exe` 和 macOS `.app`。
2. 中文、英文全局切换和用户自定义主题色盘。
3. AI 推荐与本地动漫清单为首版核心。
4. 支持标签、自然语言、喜欢和不喜欢作品输入。
5. 支持多个 AI 服务商和自定义兼容接口。
6. 用户自行提供 API Key。
7. 动漫资料需要公开数据库核验。
8. 清单记录状态、进度、10 分制评分和笔记。
9. 支持搜索后加入清单、最近 10 次推荐历史和本地备份恢复。
10. 首版范围收敛为日本/亚洲动漫优先。

### 尚需在开发前验证

1. Jikan-only 还是 Jikan + AniList 更适合首版目录策略。
2. 首批 AI 服务商预设名单。
3. macOS 签名和公证是否纳入首次公开发布。

### 当前合理假设

1. 首版不需要服务器。
2. 不采集账号和个人身份信息。
3. 网络不可用时已有清单仍可用，搜索和 AI 推荐明确不可用。
4. 目录数据缺失时显示未知，不由 AI 补写成事实。

## 3. MVP 功能边界

### 第一版必须做

1. 桌面外壳、导航、中英文和主题色盘。
2. 真实动漫目录搜索。
3. 本地清单、进度、评分和笔记。
4. 多 AI 服务商配置和系统安全凭据存储。
5. 真实 AI 推荐、结构化解析、目录核验和内容过滤。
6. 最近 10 次推荐历史。
7. 本地备份与恢复。
8. Windows 发布候选与 macOS 构建流程。

### 第二版再做

1. 推荐结果分享和导出。
2. 更完整的详情与观看顺序。
3. 评论 AI 分析。
4. 账号与云同步。
5. 全球动画覆盖。

### 暂时不做

支付、会员、社交、后台、播放、下载、自动追番通知和用户自建目录条目。

## 4. 用户流程

1. 启动软件并选择语言和主题。
2. 在设置中选择 AI 服务商、模型并保存 API Key。
3. 通过标签、文本和喜欢/不喜欢作品表达偏好。
4. 发起真实推荐请求。
5. AI 返回候选，目录服务核验并补充资料。
6. 内容策略过滤不合适或不可信结果。
7. 用户查看推荐并加入个人清单。
8. 用户维护状态、进度、评分和笔记。
9. 用户回看推荐历史并备份本地数据。

## 5. 界面语言与 UI 设计规范

界面支持中文和英文全局切换，风格轻量清爽，使用可调主题色盘。页面为推荐、搜索、我的清单、推荐历史和设置。所有网络页面必须提供空、加载、成功、部分成功、离线、超时、限流、缺少配置和错误状态。

## 6. 责任完整但不过度复杂的架构说明

覆盖页面、输入、校验、业务编排、Prompt、真实 AI 调用、结果解析、目录查询、内容策略、本地数据、历史、备份、配置、凭据、错误展示、国际化、主题、扩展接口、测试、打包和发布验证。

不引入微服务、消息队列、多租户、企业登录、插件市场、通用工作流引擎或无用抽象。采用一个仓库、一个桌面应用的模块化单体。

## 7. 推荐技术栈

- Python 3.12
- PySide6 + Qt Quick/QML
- SQLite
- keyring
- httpx
- Pydantic
- pytest + pytest-qt
- Ruff
- pyside6-deploy

首选方案与备选方案的理由见 `02-technical-architecture.md`。

## 8. 模块职责

核心模块必须具备责任、非责任、输入、输出、公开接口、内部细节、依赖、扩展点和测试重点。详细合同见 `02-technical-architecture.md`。

最重要的边界：

1. ViewModel 不直接发网络请求。
2. PromptBuilder 不调用 AI。
3. AIProviderRegistry 不解析业务结果。
4. ResultParser 不把 AI 文本当成已核验事实。
5. CatalogService 不维护用户清单。
6. CredentialService 不向日志和备份泄露密钥。
7. BackupService 不读取凭据存储。

## 9. 数据结构

首版核心结构包括 `RecommendationRequest`、`RecommendationCandidate`、
`CatalogAnime`、`RecommendationResult`、`WatchListItem`、
`RecommendationSession`、`AppSettings` 和 `BackupManifest`。字段定义和用途
见 `02-technical-architecture.md` 与 `04-data-security-ai.md`。

## 10. 分阶段开发顺序

1. Provider 与工具链可行性验证。
2. 应用外壳与设计系统。
3. 真实目录搜索。
4. 本地动漫清单。
5. AI 设置与安全凭据。
6. 真实 AI 推荐闭环。
7. 推荐历史。
8. 备份与恢复。
9. Windows 发布候选。
10. macOS 打包验证。

每次只执行一个小目标，检查失败时不得进入下一阶段。

## 11. 给 LLM 编程工具的执行要求

每次执行必须明确当前唯一目标、允许修改的文件、禁止事项、模块边界、真实 AI 规则、验收标准、检查命令、手动检查和失败停止条件。工作循环见 `08-execution-workflow.md` 与根目录 `CLAUDE.md`。

## 12. 最终自检

确认没有假结果、没有暴露 API Key、没有越过阶段边界、没有未确认功能、没有无用依赖，并且测试、文档和当天开发日志已经同步。
